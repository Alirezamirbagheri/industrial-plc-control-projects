# Public Release Checklist

Use this checklist before changing the repository from private to public.

## Ownership and licensing

- [ ] All published source code was authored by me or is clearly redistributable.
- [ ] No Siemens, Beckhoff or third-party proprietary libraries are included without permission.
- [ ] No copied training/course solution or restricted university material is included.
- [ ] License choice has been reviewed after the final file set is known.

## Security and privacy

- [ ] No passwords, API tokens, credentials or certificates.
- [ ] No license activation files, request/response files, TANs or license keys.
- [ ] No real IP addresses, AMS Net IDs, hostnames or internal network topology.
- [ ] No customer, employer, university or personal confidential information.

## Repository hygiene

- [ ] Native project archives are excluded unless specifically reviewed.
- [ ] Generated binaries, caches, logs and temporary files are excluded.
- [ ] Screenshots are sanitized and contain no machine/user paths or private identifiers.
- [ ] README clearly distinguishes implemented functionality from planned or conceptual functionality.
- [ ] Public code contains enough context to understand the engineering contribution without requiring proprietary assets.

## Portfolio quality

- [ ] Each project explains the problem, my contribution, architecture and technologies.
- [ ] Only selected high-value code or exports are included.
- [ ] At least one diagram or sanitized visual is included if it materially improves understanding.
- [ ] Claims are technically accurate and do not imply production deployment unless that was actually the case.
